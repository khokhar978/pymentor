## 4. Claude Description Error Prevention Guide

### ⚠️ What Errors Claude Was Making Previously:
When prompted previously, Claude included all of the following inside the `"description"` text:
```markdown
### Problem Description
Write a program...

### Input Format
- Line 1: ...

### Output Format
- ...

### Constraints
- ...

### Example 1
**Input:**
```
10
```
**Output:**
```
...
```
```

### ❌ Why This Caused UI Breakage:
1. **Double Examples:** PyMentor already has a dedicated **"Sample I/O"** card with an interactive "Copy" button that renders `sample_input` and `sample_output`. Claude putting `### Example 1` inside `description` duplicates the examples on the student's screen.
2. **Header Redundancy:** The PyMentor problem viewer renders the problem title as `<h1>` and a "Problem Statement" header. A leading `### Problem Description` looks repetitive and unpolished.
3. **Cluttered Reading Experience:** 1st-semester BCA beginners are overwhelmed by walls of sub-headers (`### Input Format`, `### Output Format`, `### Example 1`).

---

### ✅ The Gold-Standard Description Format for PyMentor:
Every `"description"` string must contain **ONLY**:
1. **Problem Statement:** 1 to 2 clear paragraphs explaining the real-world scenario, what inputs to take, calculations to perform, and what to print.
2. **Constraints Section (Optional / As needed):**
   ```markdown
   ### Constraints
   - Input is always a positive integer.
   - Output must be formatted to 2 decimal places.
   - Must use a while loop with // and % (no string conversion).
   ```
3. **Strictly FORBIDDEN in `"description"`:**
   - 🚫 NO `### Problem Description` or `## Description` header.
   - 🚫 NO `### Input Format` section.
   - 🚫 NO `### Output Format` section.
   - 🚫 NO `### Example` / `### Example 1` / `### Sample Case` sections.
   - 🚫 NO markdown code blocks showing sample inputs/outputs.
   - 🚫 NO `### Explanation` section.

*(All sample inputs and outputs belong exclusively in the `sample_input` and `sample_output` JSON fields!)*
